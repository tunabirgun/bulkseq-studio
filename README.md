# BulkSeq Studio

BulkSeq Studio is a cross-platform desktop application for reproducible bulk RNA-seq and microarray analysis. Its PySide6 interface drives a transparent Snakemake workflow from raw reads or processed inputs through differential expression, enrichment, protein-interaction networks, figures, reports, and route-aware provenance.

> **Release status — 11 September 2026.** Version 0.30.1 is the current public release. Use only the checksummed packages published on GitHub Releases. The separately versioned B1–B20 validation archive remains deposited as version 0.26.6 on Zenodo.

[Read the complete documentation](https://tunabirgun.github.io/bulkseq-studio/) · [Download public v0.30.1](https://github.com/tunabirgun/bulkseq-studio/releases/latest) · [View source](https://github.com/tunabirgun/bulkseq-studio) · [Report an issue](https://github.com/tunabirgun/bulkseq-studio/issues)

## What it covers

| Area | Supported routes |
| --- | --- |
| Inputs | Local single- or paired-end FASTQ; SRA/ENA accessions; RNA-seq GEO series; raw count matrices; processed microarray matrices; imported differential-expression tables |
| Read processing | FastQC/MultiQC; fastp, Trim Galore, or Trimmomatic; optional SortMeRNA or RiboDetector; optional FastQ Screen and RSeQC |
| Quantification | STAR, HISAT2, or Salmon; featureCounts, STAR gene counts, or Salmon/tximport |
| Differential expression | DESeq2 by default; optional limma-voom and edgeR quasi-likelihood; limma for microarrays; optional multi-study meta-analysis |
| Interpretation | Directional GO/KEGG and custom-gene-set enrichment, GSVA, STRING networks, publication figures, sortable reports, and Cytoscape exports |
| Reproducibility | Pinned workflow environment, content-fingerprinted pre-run validation, default-versus-used parameter records, active-route tool and reference provenance, R session details, and a `bulkseq run` command line that executes the same command the interface would |

The redesigned interface groups twelve pages into four stages: **Project and data**, **Analysis setup**, **Validate and run**, and **Explore results**. Light and dark themes apply immediately, compact windows retain every task, and the protein-network view supports pointer and keyboard navigation.

## Scientific safeguards and boundaries

Imported differential-expression tables are validated in full rather than from a preview. The importer requires unique safe identifiers and finite, in-range numeric values; records the source numerator and denominator for positive log2 fold change; binds the project copy to its hash, size, row count, and schema; and prevents stale local contrast settings from reinterpreting the imported direction. Imported-result reports do not claim that BulkSeq Studio fitted DESeq2, performed shrinkage, or used Benjamini–Hochberg unless that upstream information was supplied. Imported `.rnk` files use the confirmed `log2FoldChange`; locally fitted routes retain their model statistic.

Successful pre-run checks store content fingerprints for the configuration, configured sample sheet, local inputs, reference locks, and index files. Starting or resuming a run revalidates that state, so a replaced, edited, missing, unreadable, or unsafe linked input cannot inherit an earlier pass.

Strandedness is inferred and applied per sample rather than once for the whole project. On the STAR route each sample's library type is read from its own `ReadsPerGene` table; on the HISAT2 route it is read from a per-BAM featureCounts pass; featureCounts then counts each BAM with that sample's own `-s` value instead of one code shared by every sample. The per-sample calls are written to `results/aligned/strandedness_per_sample.tsv` (sample, code, reverse-strand ratio), and check 21 — previously run only on multi-study projects — now runs on every STAR or HISAT2 project, naming any samples that disagree within one study. STAR's `sjdbOverhang` is derived from the longest read length across every sample rather than the first sample's alone. A project where every sample already shares one library type and read length reproduces its 0.29.1 output exactly: on the bundled pasilla benchmark the 0.30.0 workflow wrote identical count-matrix bodies and a 7,532-row, 467-DE-gene DESeq2 table identical to the 0.29.1 baseline on every shared column (the two new columns aside). A project mixing library types — most often a multi-study meta-analysis pooling studies prepared with different kits — now counts each sample with its own orientation instead of forcing every sample onto one code, so its counts and downstream results can differ from earlier versions. Because the STAR index-build rule now reads every sample's FASTQ to derive the shared read length, an existing STAR project's next run re-derives that length, rebuilds its index, and re-aligns; an existing HISAT2 project re-aligns against its unchanged index, because its alignment rule now declares the summary output and index prefix. Counts are unchanged in both cases when every sample already shared one library type.

A new pre-run screen, check 23, guards against unmodelled structure reaching a DESeq2 design. For every sample-sheet column outside the design formula — file paths, accessions, and other ingest metadata are excluded, and a numeric column is still treated as categorical — the workflow fits a one-way ANOVA of that column against the run's PC1 and PC2 coordinates (written to `results/deseq2/pca_coordinates.csv`) and reports the adjusted R² and the F-test p-value with the call. A column is `REVIEW_REQUIRED` only when its adjusted R² exceeds 0.5 *and* its p-value is below 0.05, so a column's shape alone cannot trigger it on noise; a column whose grouping exactly coincides with the contrast factor is reported as aliased with it instead of screened, since its effect cannot be distinguished from the contrast. Single-level and all-distinct columns are skipped. The screen runs on every DESeq2-engine route — single-study fastq, count-matrix, and multi-study meta-analysis — and does not run for microarray (limma), limma-voom, or edgeR quasi-likelihood, which do not write the PCA coordinate file it reads.

A shared cluster or lab can point a project at reference artifacts it already built instead of rebuilding them per project. Setting `reference.star_index`, `hisat2_index`, or `salmon_index` to an existing path skips the matching index-build rule; `hisat2_index` names the hisat2-build prefix, not a directory. Setting `reference.transcriptome_fasta` makes the Salmon index build (or, with `salmon_index` also set, the quantification) use your FASTA, but the gffread transcriptome step still runs against the genome and annotation, because the transcript-to-gene map is derived from the annotation and is not replaced; before tximport, the workflow now verifies that every transcript name Salmon reported appears in that map and stops, naming `salmon_index`/`transcriptome_fasta` as the likely cause, instead of silently zeroing the affected genes on a mismatch. A configured but missing path is refused at validation, before any job runs, naming the setting. `reference.protein_fasta`, which no rule ever read, is removed from the configuration model; a value left over in an existing project's configuration now produces a warning instead of being silently accepted.

Run provenance now names the environment that actually executed the run, not only the lock file the repository ships. `run_summary.json` gains an `environment_spec` record — the installed spec file's name, its SHA-256, and whether it came from the pinned lock, the core profile, or a floating fallback solve (`unknown` for an environment set up before 0.30.0) — alongside the unchanged `environment_lock_md5`, which continues to hash the repository's own lock file regardless of what was actually installed; the two can now disagree, which makes a fallback-solved environment visible instead of indistinguishable from a lock-installed one. `run_summary.txt` and `tools_references.txt` print the installed spec next to the lock hash.

A `bulkseq run [--mode run|dry-run|resume] [--exec-profile local|slurm|kubernetes]` command line now runs the workflow to completion, not only to a dry-run or a printed command. It builds its Snakemake invocation through the same command builder the interface and `bulkseq print-command` use, so a scripted or scheduled run cannot silently diverge from what the interface would launch, then streams the run's output and exits non-zero on failure — including a `micromamba run` masked exit code the interface already screens for. `--mode resume` against a run a previous crash or interrupt left locked unlocks it first, mirroring the interface's own resume path, rather than refusing to start against a locked directory.

> **Meta-analysis correction.** Releases before 0.26.6 adjusted p-values across every gene and then removed direction-discordant genes from the called set. Re-run any multi-study result produced with 0.26.5 or earlier. Single-study differential expression, enrichment, and network output are unaffected.

> **0.29.0 output changes.** GSEA now ranks on the model test statistic, STRING seeding is split by direction in adjusted-p order, meta-analysis combined p-values are computed in tail form so strongly concordant genes are ranked instead of tied at zero, and genes-of-interest heatmaps use a zero-anchored colour scale. Results produced with 0.28.0 or earlier can differ in enrichment tables, network membership, and figure ordering; re-run before publishing. [CHANGELOG.md](CHANGELOG.md) lists every change in the release.

> **0.30.0 output changes.** *S. pombe* KEGG enrichment now reaches its tables through a measured NCBI GeneID bridge instead of returning empty results, and strandedness is inferred and applied per sample rather than once per project, so a run mixing library types now counts each sample with its own orientation. An existing STAR project's next run re-derives the read length across all samples, rebuilds its index, and re-aligns, and an existing HISAT2 project re-aligns against its unchanged index; counts are unchanged when every sample already shared one read length and library type, and differ only for a mixed run. [CHANGELOG.md](CHANGELOG.md) has the complete entry.

0.30.0 carries two kinds of installation evidence. In continuous integration, the Windows installer build silently installs the freshly built package, runs its frozen self-test, reinstalls over the update branch, and uninstalls; the R test job runs the Bioconductor-dependent figure contracts against a cached micromamba layer pinned to the pipeline's own R/Bioconductor builds; a static job lints the WSL/native-Linux setup script; and a separate Environment workflow installs the core and full profiles live on changes to the script or environment specs, weekly, and on demand. CI runners keep caches, so none of that is clean-machine evidence. Separately, on a fresh, disposable WSL Ubuntu 24.04.4 distribution created for this release and removed afterwards, the full environment installed from the pinned lock file (5.5 and 8 minutes on two fresh distributions), every installed tool reported its version, the R stack loaded, and a synthetic yeast count-matrix project from the 0.29.0 validation reproduced its previously recorded 709 differentially expressed genes end to end. Re-running the installer on the finished environment changed nothing and finished in under two minutes; after an R package was deliberately removed, the installer refused an unrequested rebuild, named the broken packages, and the authorised rebuild (`BULKSEQ_REBUILD=1`, the Rebuild button in Check Environment) recovered the environment in 6.5 minutes; with no network, the installer stops with a one-line message naming the download URL and the cause.

### What changed in 0.30.1

- `run_summary.json`, `run_summary.txt`, and `tools_references.txt` report the app and workflow version that actually executed, read from `workflow/workflow_metadata.yaml` (the app now records its own version there when it copies the workflow; a copy made before 0.30.1 reports the app version as not recorded); the project's creation-time app and workflow versions are kept as separate `project_created_app_version` and `project_created_workflow_version` fields, and the JSON also carries the workflow digest and copy timestamp.
- `bulkseq run` re-syncs an outdated project's workflow copy before building the Snakemake command, as the graphical interface already did.
- The Windows and Linux release artifacts exclude the git-tracked GUI benchmark harness under `installer_output/gui-benchmark-runs/`, and the warm-theme-toggle timing test holds only the warm toggles to its ceiling, with a negative control that proves the gate still fails on a forced slow path.

### What changed in 0.30.0

- *S. pombe* KEGG enrichment reaches its tables through a measured NCBI GeneID bridge instead of returning empty results: before a raw-locus-tag KEGG query the workflow probes the organism's live KEGG gene list, and only when the keys are observed to be bare NCBI GeneIDs (recorded as `kegg_key_form_observed`) does it bridge the RefSeq locus-tag gene ids to NCBI GeneIDs through the GTF's `db_xref` field. Measured: 0 of 50 test genes mapped before the fix, 18 of 50 after, against a universe of 2,061; every earlier *S. pombe* KEGG ORA/GSEA table was empty. Organisms whose KEGG keys are observed to be locus tags (*Fusarium graminearum*, *Candida albicans*, and others) are unchanged, a failed probe applies no bridge, and the limma-voom and edgeR routes do not yet carry the GeneID column, so *S. pombe* KEGG remains unmapped there.
- Strandedness is inferred and applied per sample: STAR reads each sample's own `ReadsPerGene` table, HISAT2 runs a per-BAM featureCounts pass, and featureCounts counts each BAM with that sample's own `-s` value, written with the code and reverse-strand ratio to `results/aligned/strandedness_per_sample.tsv`. Check 21 now runs on every STAR/HISAT2 project, not only multi-study ones, and flags disagreeing samples within a study by name and ratio; `sjdbOverhang` derives from the maximum read length across every sample. Verified on the bundled pasilla benchmark: 0.30.0 and 0.29.1 produce identical count bodies and a 7,532-row, 467-DE-gene DESeq2 table identical on every shared column. A run mixing library types now counts each sample with its own orientation instead of one orientation for all, and an existing STAR project's next run re-derives the read length, rebuilds its index, and re-aligns, and an existing HISAT2 project re-aligns against its unchanged index.
- Check 23 (covariate structure): a one-way ANOVA of PC1/PC2 against every sample-sheet column outside the design formula, on DESeq2-engine routes; `REVIEW_REQUIRED` requires adjusted R² above 0.5 and an F-test p-value below 0.05, and a column aliased with the contrast factor is reported as such instead. PCA coordinates are written to `results/deseq2/pca_coordinates.csv`.
- Check 06 (uniquely-aligned-fraction) now covers the HISAT2 route from its own alignment summary, at the same 70%/50% warning/review-required thresholds already used for STAR.
- Two new DESeq2 table columns: `padj_lfc_ge_threshold` (the adjusted p-value of a `greaterAbs` test at the configured log2 fold-change threshold; informational, and does not change the primary significance call) and `ncbi_geneid` (from the GTF's `db_xref`, where present).
- KEGG evidence now records its UTC retrieval date and the installed KEGGREST and clusterProfiler versions.
- Prebuilt reference inputs: `reference.star_index`, `hisat2_index`, and `salmon_index` skip the matching index-build step when set to an existing path, and `transcriptome_fasta` is used in place of the generated transcriptome for the Salmon index while the gffread step still runs to derive the transcript-to-gene map; a set-but-missing path is refused at validation; a mismatched prebuilt Salmon index/transcriptome is caught before tximport instead of silently zeroing genes; `reference.protein_fasta`, never read by any rule, is removed (a leftover value now warns instead of being silently accepted).
- `run_summary.json` records the installed environment spec — file, SHA-256, and whether it came from the lock, the core profile, or a fallback solve — alongside the unchanged environment lock hash.
- `bulkseq run [--mode run|dry-run|resume] [--exec-profile ...]` runs the workflow to completion from the command line through the same command builder as the interface, exiting non-zero on a failure the launcher would otherwise mask.
- Check Environment probes every installed WSL tool in one call instead of one call per tool.
- CI now silently installs, self-tests, reinstalls, and uninstalls the built Windows package; runs the Bioconductor-dependent figure contracts on a cached R/Bioconductor layer; lints the setup script statically; and runs a separate scheduled workflow that installs both environment profiles live. `constraints.txt` pins the application's own Python dependencies in both CI and packaging.

### What changed in 0.29.0

- GO, KEGG, and custom GSEA rank genes on the signed model test statistic (DESeq2 Wald, limma or voom moderated *t*, edgeR signed root-F), the metric the exported preranked file already used; the enrichment summary names the ranked column.
- STRING seeding divides the seed cap between the up- and down-regulated genes in adjusted-p order, passing unused budget from the smaller direction to the larger one, and records the realized up and down seed counts in the network provenance.
- The meta-analysis inverse-normal combination is computed in tail form, so a combined |Z| above about 8.3 no longer collapses to exactly zero and the most significant genes are ordered by evidence; the p-value still reaches exactly zero once the combined |Z| exceeds about 38, which requires per-study p-values near the double-precision floor (an exact 0 from DESeq2 is clamped to 2.2e-308, |Z| 37.5), and the meta-volcano marks such genes as off-scale.
- Genes-of-interest and enrichment-term heatmaps use a zero-anchored, symmetric colour scale, matching the top-DEG heatmap.
- The volcano plot uses the unshrunken effect, so its guides, colouring, and ranked side key share the coordinate the up- and down-regulated tables report; the MA plot keeps every gene with a finite mean, including the independently filtered low-count cloud.
- KEGG over-representation and KEGG GSEA are audited and reported per leg, so a comparison with too few significant genes for over-representation still returns its ranked-list pathways.
- A local microarray matrix with text tokens or comma decimals is refused, with the offending values named, rather than silently converted.
- A design term that holds only numeric values is fitted as a continuous trend; the design check now flags it for review and the design helper labels the column.
- The SortMeRNA rRNA database and micromamba are fetched at pinned versions and verified against recorded SHA-256 digests before use.
- Check Environment reports against the installed profile, so full-only tools and the R stack read as not applicable on a core environment instead of as failures.
- The Windows installer refuses to run while BulkSeq Studio is open, so an update cannot remove the previous version and then abort on a file in use.

The deposited B1–B20 validation suite belongs to version 0.26.6. Its multi-study result depends on replication: at five replicates per group the combination gained 11–37 true positives over the best constituent study in ten of ten runs, whereas at ten replicates it ranged from 16 fewer to 14 more and failed that power criterion in five of ten. Complete-null calibration was not established for the smallest design: two-study combinations at five replicates per group rejected in 2 of 5 independent seeds, with an exact lower confidence limit of 0.053 that failed the criterion; three-study combinations rejected in 1 of 5. Both strata fell inside the bound at ten replicates. All 1,326 observably opposite-direction planted genes were flagged and none was called. The real two-study dexamethasone arm is corroborative, not a general power claim.

The archived benchmark tables, negative controls, method-specific qualifications, and platform limits remain available in the checksummed Zenodo deposition cited below. The deposited 0.26.6 archive's enrichment tables, STRING network membership, and volcano/MA/genes-of-interest figures predate the 0.29.0 GSEA-ranking, seed-splitting, and colour-scale changes and will be regenerated in a later archive version; the differential-expression gene counts are unchanged. The archive also predates the two 0.30.0 output changes. None of its deposited studies uses *S. pombe*, so its KEGG tables are unaffected by the GeneID bridge; its differential-expression gene counts were not re-run under 0.30.0; per-sample strandedness leaves counts identical for a uniform-library study (verified on pasilla) and was not re-checked for the archive's multi-study arms, so treat those counts as unverified against 0.30.0 until the next archive version.
