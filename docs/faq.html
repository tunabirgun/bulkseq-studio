Help

FAQ & troubleshooting

Short answers to the questions that come up most often.

Release status Version 0.26.6 is the current public release. Use only the checksummed packages published on GitHub Releases.

Do I need to know how to code?

No. The whole pipeline runs from a guided graphical interface. Project and data, Analysis setup, Validate and run, and Explore results group the same tasks into four stages; wide windows use a stage rail and compact windows use stage and page selectors. No command line is required.

What do I need on Windows?

Windows 10 or 11 (x64) and WSL2, the Linux subsystem the pipeline runs inside. The app can enable WSL2 and install the bioinformatics environment for you from its Environment setup screen. Enabling the WSL feature is the one step that needs administrator rights (Windows requires it) and may ask for a reboot; everything after that runs without elevation.

The first-run environment setup is slow. Is that normal?

Yes, and it is one-time. The core bioinformatics environment downloads over several minutes, and the R / DESeq2 stack is the largest, slowest install. You can keep creating projects, editing metadata, and generating configs while it installs; only starting a pipeline run needs the tools in place.

Do I have to remember to check the environment before my first run?

No. On the first launch after install the app opens the Check Environment dialog automatically, once, so a missing tool such as the R/DESeq2 stack is flagged up front rather than mid-run; you can reopen it any time from Check Environment on the Project page.

Does it work on Linux without WSL?

Yes. On Linux the same GUI drives the same Snakemake pipeline natively in a local micromamba environment, with no WSL involved, and produces identical results. There is no WSL setup step and no memory cap below the host's RAM.

How do I update to a new version?

Use only an approved artifact. The current public release is 0.26.6. On Windows, a newer approved installer detects the existing install and offers to update or uninstall first; a portable ZIP is replaced by unpacking the new archive. On Linux, after a newer version is publicly released, download its AppImage or use AppImageUpdate with the published companion zsync information.

Which trimmer, rRNA tool, and DE engine should I use?

The defaults are chosen to work for a standard study: fastp for trimming, SortMeRNA if you turn on rRNA removal, and DESeq2 for differential expression. Change them only when you have a reason. Prefer Trim Galore or Trimmomatic if your lab standardizes on one; use RiboDetector when no rRNA reference is available for your organism; and run limma-voom or edgeR quasi-likelihood as a cross-check, especially on larger designs. All the alternatives produce the same tables and figures, so downstream steps do not change.

My organism has no Bioconductor annotation package (a crop or fungus). Can I still get enrichment and networks?

Yes. Without an OrgDb you still get KEGG pathway ORA and GSEA for any organism with a KEGG code, plus GO through g:Profiler (gprofiler2), and the STRING protein-interaction network is unaffected. An organism is not skipped for lacking an OrgDb.

Can I run single-end reads?

Yes. Single-end and paired-end input both run the full alignment route through every trimmer, aligner, and rRNA tool; the app detects the layout from the sample sheet. A single run must use one layout — a mixed-layout sample sheet is rejected with guidance so the two are not counted together.

I already have processed data. Can I skip the download and alignment?

Yes. Three choices on the Add data page take pre-computed input straight into the analysis. Use a Count Matrix ingests a gene × sample count table and skips download, QC, and alignment, running DESeq2 → figures → enrichment. The table must be raw integer counts; normalized values are refused by default, while RSEM/tximport estimated counts can be opted in. Upload DESeq2 Results starts from an external differential-expression table and skips to the applicable figures, enrichment, and STRING network. The complete table is validated, its fold-change direction must be confirmed, and the project copy is bound to its hash, size, row count, and schema; no local DESeq2 model is claimed. Upload a local microarray matrix takes already-normalized log2 intensities and runs the limma route with no accession or download.

Can I combine two studies or BioProjects of the same comparison?

Yes, with the multi-study meta-analysis. Put the samples of every study in one project, give each row a dataset value (its study of origin) and a condition value on the Samples page, then enable Multi-study meta-analysis on the Analysis settings page. Each study is analysed separately with DESeq2 and the per-study statistics are combined (metaRNASeq inverse-normal p-values and metafor effect-size pooling), so platform and depth differences stay within a study. Genes whose direction disagrees across studies are flagged discordant and are never called cross-study hits. A separate meta_analysis_report.html, the results/meta/ tables, and comparative figures are written alongside the standard outputs. At least one study must contain both compared groups (otherwise the comparison is perfectly confounded with study and the run is blocked), and the studies must share one organism and one gene-identifier namespace.

How much disk space and memory do I need?

About 10 GB of free disk for the toolchain and reference indices, and 16 GB or more of RAM is recommended. STAR alignment is the memory-intensive step; for very large genomes use the HISAT2 or Salmon aligner, which need far less.

My custom gene sets returned nothing. Why?

Almost always an identifier-namespace mismatch: the gene IDs in your GMT or annotation table must match the run's ID format. A mismatch is flagged, with examples of the run's IDs. Use Ensembl gene IDs for human and mouse, FlyBase for Drosophila, and NCBI GeneIDs (bare or LOC<GeneID>) for NCBI-RefSeq crops such as rice.

Where do my results go, and how do I re-make just the figures?

Everything lands in the project folder; open it from Open Project Folder on Run monitor. To restyle figures, use the built-in Figure Style inspector on Figures and tables and click Regenerate figures; this re-renders them without re-running alignment or differential expression.

Can I change between light and dark mode while a project is open?

Yes. The persistent header control switches the main window, dialogs, plots, status surfaces, and embedded protein network immediately and saves the choice for the next launch. It does not change the open project, current page, or analysis settings.

A console window flashed on screen during a run. Should I close it?

No. On Windows a WSL/terminal window may briefly appear because the app launches Snakemake inside WSL2. Closing it kills the running pipeline. Use the Stop button in the app to cancel a run instead.

Does my computer's language or region change how numbers are read?

No. Regardless of the operating-system locale — including comma-decimal languages such as Turkish or German — the app always uses a dot as the decimal separator in every numeric field, and exports LC_NUMERIC=C to the pipeline so R and the command-line tools read and write dots too. A numeric setting such as alpha or |log2FC| therefore behaves identically on any machine. A comma hand-edited into a config is normalized back to a dot when the project is loaded, with a short notice.

If a run pauses and asks to stop or continue That is the low-mapping safeguard: a sample aligned poorly (uniquely-mapped rate below the threshold), usually a wrong reference or contamination. Check your reference and sample sheet before choosing to continue.

Cite & license

BulkSeq Studio is free and open-source software released under the MIT License. You can install it, use it, study the code, and share it at no cost. The accompanying manuscript is in preparation for submission to a peer-reviewed journal.

How to cite

If you use BulkSeq Studio or its validation archive in your work, please cite the software and the reproduction archive deposited on Zenodo. The archive (version 0.26.6, DOI 10.5281/zenodo.21833538; the concept DOI 10.5281/zenodo.20955660 always resolves to the latest deposited version) holds the validation scripts, the pinned scoring environment, the result tables and figures, and a reproduction guide.
