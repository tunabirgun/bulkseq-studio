Analysis routes#

BulkSeq Studio keeps raw-read, count-matrix, microarray and supplied-result routes distinct. Read processing and quantification apply only to raw reads; a supplied counts matrix enters the shared count-analysis path; microarrays use limma; supplied differential-expression tables are normalized into the reporting path without refitting a count model. The project record states the route, settings and realized analysis software for each run.

For raw RNA-seq, the workflow can inspect reads with FastQC and MultiQC, trim with fastp, Trim Galore or Trimmomatic, optionally screen contamination or rRNA, then use STAR or HISAT2 alignment with featureCounts, or Salmon plus tximport. These routes produce the same downstream count-table contract, but their read assignment strategies differ. Select a route that is justified by the library, reference and study question rather than expecting interchangeable results.

Workflow execution and retrieval

Snakemake builds the dependency graph and records outputs, checks and logs for the selected route. It does not choose a biological model. For public FASTQ retrieval, the workflow uses aria2 with up to four connections per file and resumable retries when it is available, then falls back to a single stream. Downloaded reads are checked against the provider’s configured MD5 before analysis.

From reads to counts

FastQC measures per-read quality summaries before and after trimming; MultiQC aggregates the tool reports. fastp is the default adapter and quality trimmer. Its defaults define a qualified base as Phred 15, discard reads with more than 40% unqualified bases, and retain reads of at least 36 bases; poly-G and poly-X trimming are off. Those values change which reads enter counting. Trim Galore and Trimmomatic are alternatives: the shared quality and length settings carry over, while Trimmomatic also uses adapter clipping, leading/trailing quality 3 and a 4-base window at quality 15. The three routes emit the same file shape for later steps, not necessarily the same retained reads.

Optional SortMeRNA builds an index from the configured rRNA database and sends rRNA-matching reads away from the alignment input; its paired-end mode defaults to paired_in. Optional RiboDetector is reference-free and defaults to ensure = norrna with chunk size 256. FastQ Screen samples up to 100,000 reads against a user-supplied reference panel and reports contamination; it does not remove reads. RSeQC adds genomic-distribution and gene-body-coverage diagnostics when a genome BAM exists.

Alignment and gene-level quantification

STAR maps reads to a genome and produces a coordinate-sorted BAM plus its own gene-count table. Its default route permits up to 10 mapping loci, allows a mismatch fraction of 1.0, and has two-pass splice-junction discovery off; enabling two-pass mode changes the alignment procedure and is slower. HISAT2 also maps to a genome and its BAM is counted with featureCounts. Salmon uses mapping-based transcript quantification directly from trimmed reads, with mapping validation and paired-end GC-bias correction when applicable; tximport then aggregates transcript estimates to genes with lengthScaledTPM.

featureCounts sums reads over the configured annotation feature type and attribute, defaulting to exon and gene_id. The workflow determines strandedness per sample for genome-alignment routes; changing a fallback strandedness value is not a substitute for a compatible library and annotation. The associated methods are described by Dobin et al. (STAR), Kim et al. (HISAT2), Patro et al. (Salmon), Liao, Smyth and Shi (featureCounts) and Soneson, Love and Robinson (tximport).

Parameter choices#

Start with a sample sheet that identifies the biological factor, its reference level, the planned numerator and denominator, and any defensible covariates. The default count-model settings are ~ condition, control as the condition reference, adjusted-p threshold 0.05, raw |log2 fold change| screen 1, minimum count 10, and requested apeglm shrinkage. They are starting defaults, not universally optimal values.

  • Reference and annotation: Use a FASTA, GTF/GFF and gene identifier namespace that belong to the same assembly. Changing them can change the feature universe and read assignment.
  • Read processing: Enable trimming or optional QC only when the reads and study protocol support it. Trimming, rRNA handling and the aligner/quantifier change the input counts; the contamination screen is a report, not a filter.
  • Model: The design formula determines the fitted model. Include known covariates only when they are measured, relevant and leave a full-rank design. If the comparison factor participates in an interaction, its main-effect contrast is conditional on the other interacting terms: factor reference levels and zero for numeric covariates. BulkSeq Studio provides a factor/numerator/denominator contrast only; testing an interaction requires a separately specified DESeq2 analysis.
  • Calling lists: In the default DESeq2 route, padj < alpha and the raw, unshrunken |log2 fold change| screen create the up- and down-regulated lists. Shrunk fold changes support stable display and ranking; they do not replace that list rule. The additional effect-size screen does not itself supply an FDR guarantee for the selected subset.

Changing a display cutoff in a figure changes which already fitted rows are highlighted. It does not refit the model, change the p-values, or rescue a confounded design. Re-run the workflow after changing an analysis setting and compare the resulting project records.

What the default count analysis fits

DESeq2 fits a negative-binomial count model. Its independent-filtering step determines the eligible adjusted-p family, and Benjamini–Hochberg adjustment is applied within that family; rows excluded from adjustment have NA adjusted p-values. The main implementation uses DESeq2’s Wald contrast; the separate threshold test uses lfcThreshold and answers a different question. apeglm shrinkage is requested for fold-change presentation; if that coefficient fit fails, the workflow records an ashr fallback. These procedures follow Love, Huber and Anders (DESeq2), Zhu, Ibrahim and Love (apeglm), Stephens (ashr) and Benjamini–Hochberg.

Optional limma-voom and edgeR-QLF routes use their own estimators and model parameterization. They are useful sensitivity analyses when their assumptions and contrast are appropriate; agreement or disagreement is evidence to inspect, not an automatic verdict. The implemented routes are based on limma-voom and edgeR.

Supported formulas and the fitting boundary

All four local DE engines parse one one-sided formula beginning with ~. The parser permits formula operators and the transformations I, log, log2, log10, log1p, sqrt, abs, scale and poly; arbitrary R calls are refused. DESeq2 can use the supported transformations and operators, subject to model identifiability and the selected contrast. Syntax support does not establish that a transformation is scientifically appropriate.

The alternative engines impose the narrower additive contract described below. For example, ~ batch + condition is supported, while ~ condition + log(age) and ~ condition + age - age are refused. The guard runs at the R model stage before fitting; current Python pre-run checks do not duplicate every restriction. Preserve necessary covariates and choose a suitable model rather than simplifying the scientific question to satisfy the software. See the formula reference.

Normalization, filtering and microarray scope

DESeq2 prefilters genes with at least the configured count in at least the smallest contrast group, then estimates size factors and dispersions in its count model. limma-voom and edgeR-QLF instead use edgeR’s filterByExpr and TMM normalization; voom estimates observation-level precision weights before limma’s moderated fit, while edgeR fits a quasi-likelihood model. Neither alternative route performs DESeq2 fold-change shrinkage. Their implemented group-means parameterization requires additive bare sample-sheet variables, including the selected contrast factor, and accepts intercept terms 0, 1 and -1. It rejects transformations, interactions, nesting, dot expansion and removal of variables rather than discarding those operations. The same restriction applies to microarray limma.

For microarrays, a GEO series matrix is treated as submitter-normalized expression data, whereas raw Affymetrix CEL files are processed with RMA. The workflow converts to a gene-level log2 matrix, retaining only unambiguous probe-to-symbol mappings and collapsing duplicate probes by MaxMean before limma. It does not make different array platforms, preprocessing histories or probe definitions comparable by itself.

Meta-analysis#

Multi-study mode requires a dataset column and at least two studies with both selected contrast arms and at least two samples per arm. Each eligible study receives a full DESeq2 fit using only ~ selected_factor; HTSFilter then filters that fitted object, and results are extracted with independent filtering disabled. The workflow does not refit DESeq2 after HTSFilter. A requested joint model is recorded separately and may be ~ selected_factor + dataset; it is not the formula used for the per-study fits.

Only genes shared by every eligible study and complete for p-value, unshrunken log2 fold change and its standard error are combined. Studies or genes that fail those requirements remain documented in the eligibility record instead of being silently treated as evidence for no effect.

Combined p-values and the concordance rule

For a shared complete-case gene, the workflow combines the per-study two-sided Wald p-values by a replicate-weighted inverse-normal statistic. With total included-study sample count nj, its weight is wj = √(nj / Σnj). The statistic is Z = Σwj × qnorm(1 − pj), and the combined upper-tail p-value is pnorm(Z, lower.tail = FALSE). The implementation evaluates the quantile and tail probability directly, avoiding precision loss from explicitly forming 1 − p for very small p-values. These weights use total selected samples only; they are not inverse-variance, study-quality or arm-balance weights.

A combined adjusted p-value is calculated with Benjamini–Hochberg only for the family whose unshrunken effects have matching, nonzero signs in every included study. Rows with discordant or zero signs retain their raw combined p-value but have no combined_padj and are never meta-DEGs. Therefore meta_sig means combined_padj < alpha; no log2-fold-change threshold is added. The matching-sign restriction is determined from the observed effects, so this documentation does not assert FDR calibration for arbitrary datasets. The p-value method is from Rau, Marot and Jaffrézic (2014); HTSFilter is described by Rau et al. (2013).

Pooled effects are a second analysis

The workflow separately pools unshrunken log2 fold changes and their standard errors with metafor: fixed effect for two studies and DerSimonian–Laird random effects for three or more. Standard errors are floored at 1e-6 for the fit. Its rem_padj uses Benjamini–Hochberg across every estimable pooled-effect test, including discordant or zero-sign rows. This answers a pooled-effect hypothesis, not the inverse-normal combined-p hypothesis. With two studies, tau2, I2 and QEp are deliberately NA because the workflow does not report heterogeneity fields with so little information. The default metafor inference is z-based Wald inference; pooled estimates and intervals are exploratory with few studies, where nominal coverage and error control can be unreliable. See metafor’s recommendations. The model implementation follows Viechtbauer (2010).

Results produced before v0.34.0 need recomputation before their pooled adjusted values are interpreted: rem_padj already existed, but now uses Benjamini–Hochberg across every estimable pooled test. The matching-direction combined calls are unchanged.

Methods and limits

These are constructed effect estimates and standard errors, not fitted biological studies. Every displayed fit was computed with metafor using DerSimonian–Laird random effects and z-based Wald intervals, as in BulkSeq’s pooled branch for three or more studies. Square area reflects normalized inverse-variance weight after adding estimated between-study variance; omitted studies have no weight.

All-studies and leave-one-out views retain at least three studies. With so few studies, uncertainty and heterogeneity estimates can be unreliable. This illustration does not compute combined p-values, adjusted p-values or meta_sig; a pooled interval is not a combined-p significance call. Removing a study is a sensitivity exercise, not permission to discard inconvenient evidence.

Neither a combined p-value nor a pooled effect proves replication, causality, independence of studies or biological consistency outside the included datasets. Inspect study eligibility, identifiers, reference compatibility, effect directions, covariates and heterogeneity before making those claims.

Annotation and enrichment#

The workflow annotates supported identifiers through GTF-derived fields and Bioconductor annotation resources, and can run GO, KEGG and custom-set enrichment with clusterProfiler. The optional g:Profiler route sends queries to its online service; its retrieved database content is time-dependent and is recorded with the run rather than assigned a package-lock version. Enrichment summarizes annotations among a selected gene set; it does not establish a pathway mechanism or validate a differential-expression result.

Over-representation, ranked enrichment and sample-level scores

Over-representation analysis tests the selected up- or down-regulated list against its applicable annotated background. The background and foreground can shrink when identifiers are unmapped or ambiguous, so inspect the recorded effective populations rather than treating the configured list size as the tested universe. Ranked GSEA tests whether set members concentrate near either end of an eligible gene ranking. Built-in GO/KEGG GSEA uses the signed stat column when finite statistics are available, falling back to raw log2FoldChange otherwise; imported results use a supplied direction-checked statistic, with missing statistic values filled by raw fold change. The external .rnk export for imported results and custom gene-set GSEA both rank on raw log2FoldChange. These ranking metrics answer different questions, so inspect the route’s recorded ranking evidence. g:Profiler supplies an ORA-only GO route, so it does not create the local ranked-GSEA result. Optional GSVA scores samples against a supplied custom GMT using the log-scale matrix already appropriate to the route: VST for DESeq2, logCPM for voom/edgeR, or log2 intensity for microarrays.

Empty results and unavailable analyses

A successful enrichment computation can return no retained terms. In custom ORA/GSEA and cross-study enrichment, an error during execution or result conversion is instead recorded as REVIEW_REQUIRED, with the affected output unavailable. Inspect check 24 for custom sets and check 18 for cross-study enrichment, together with their summaries and logs. A blank table without successful execution evidence does not establish a negative finding; other mapping and eligibility checks can also require review.

Version 0.35.0 tests these distinctions and supported additive-model invariance with synthetic fixtures. The nine bundled biological datasets have not been rerun under this version. Review older analyses that used unsupported alternative-engine formulas or reported empty enrichment despite an execution error. The pooled-effect and combined-p testing families introduced in 0.34.0 retain their definitions.

STRING and cross-study enrichment

The optional STRING network maps the selected genes to STRING identifiers, retrieves their association graph and keeps edges with combined_score at or above the configured threshold, default 400 on STRING’s 0–1000 scale. The score integrates physical and functional evidence; an edge is not proof of a direct physical interaction. The graph can be empty when mapping, organism coverage or the online service is unavailable, and the report records that state.

In multi-study mode, cross-study enrichment compares per-study and convergent gene sets on one shared universe. Per-study enrichment is a separate opt-in step and is off by default because it runs enrichment for each eligible study. These summaries do not turn the combined result into an independent replication experiment.
