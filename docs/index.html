BulkSeq Studio documentation

Reproducible bulk RNA-seq and microarray analysis, from raw reads or processed inputs to a reviewable result.

BulkSeq Studio is a cross-platform desktop application that drives a transparent Snakemake workflow. Its interface configures read processing, gene quantification, differential expression and downstream interpretation; you can also enter later with counts, microarray intensities or a completed differential-expression table. A shortcut skips earlier work, but it does not reconstruct measurements you do not have.

Note

Release 0.32.1

This handbook documents release 0.32.1, which corrects documentation, the command line, and interface and installer faults, and leaves every analysis output as 0.32.0 produced it. The last release to change scientific output was 0.32.0: its corrections can change malformed-count handling, ambiguity-sensitive mapping and enrichment or cross-study selections, and synthetic regressions establish those contracts. Under 0.32.1 all seven bundled datasets were rerun through the installed interface and passed: every run completed without a FAIL, pasilla, rice and both Fusarium datasets reproduced their recorded results, and the other three have their first recorded values, listed in the tutorial.

What it covers#

Inputs are local FASTQ, SRA and ENA accessions, RNA-seq GEO series, raw count matrices, processed microarray matrices and imported differential-expression tables. Quantification uses STAR, HISAT2 or Salmon with featureCounts, STAR gene counts or tximport. Differential expression uses DESeq2 by default, with limma-voom and edgeR quasi-likelihood as alternatives and limma for microarrays. Interpretation covers directional GO and KEGG enrichment, custom gene sets, GSVA, STRING networks, publication figures and sortable reports.

What it is not#

This is a bulk-expression analysis tool, not a single-cell workflow, a clinical diagnostic system or an automatic explanation of biological causation. A successful run means the computation completed; the study design, the quality checks and the interpretation still require your review.

If something goes wrong#

Start with the checks, which name the problem more precisely than a failed run does, then troubleshooting. The glossary defines the terms the interface uses.
