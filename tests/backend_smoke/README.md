# Manual full-backend smoke

The Environment workflow installs the shipped full Linux profile. A manual dispatch with `full_smoke=true` then runs these numbered phases on the installed environment, one job and one CPU at a time. Push, pull-request, and scheduled environment runs retain their existing installer checks without this optional suite. The suite uses fixed synthetic sequence and count fixtures; its yeast STRING seeds are the public identifiers CDC28, CLB2, and SIC1. It tests executable function and output contracts, not biological accuracy, benchmark performance, or the local Windows/WSL font path.

The workflow runs each script from the repository root with `BULKSEQ_SMOKE_ROOT` set to a fresh runner-temporary directory. `01_prepare.py` copies the current shipped `workflow/` into isolated projects. The full environment is the exact installed profile from `workflow/envs/bulkseq.lock.yaml`; fixture seeds are 3400 for sequence and 3401 for negative-binomial counts. The setup installer records the selected environment and checks its declared package identities before the smoke starts.

| Phase | Inputs and command | Required output and gate |
|---|---|---|
| 00–01 | `python 00_profile.py "$BULKSEQ_SMOKE_ROOT" prepare`; `python 01_prepare.py` | At least 3 GiB available RAM and 1 GiB free disk; six isolated projects, 27 planted reads, 80 genes in eight synthetic samples. |
| 02 | `bash 02_salmon.sh`; `python 02_check_salmon.py` | Shipped Salmon and tximport rules; transcript reads reconciled to planted exon membership, and gene counts checked against the configured `lengthScaledTPM` formula and rounding. With one sample and one transcript per gene, this fixture cannot distinguish that estimator from raw-count behavior. |
| 03 | `python 03_packaged_model.py`; `bash 03_ribodetector.sh`; `python 03_check_ribodetector.py` | RiboDetector's installed packaged model, actual classification, and exact FASTQ ID/sequence/quality partition. The random synthetic reads are not an rRNA accuracy test. |
| 04–05 | `bash 04_main.sh`, `bash 05_meta.sh`, then their checkers | Shipped DESeq2/main figures/report and two-study meta result/report; independently recalculated full pooled-effect BH family. |
| 06–07 | `python 06_legacy_reporting.py`; `bash 06_custom_old.sh`; `bash 07_custom_new.sh`; `python 07_check_custom.py` | Two analytic custom-enrichment reruns on identical inputs and runtime. The old variant changes only the reviewed reporting tail after saved model objects; ORA/GSEA CSV and RDS bytes must match, and supplied versus annotated populations must agree with independent GMT/DE intersections. |
| 08–09 | `bash 08_gsva.sh`, `bash 09_custom_report.sh`, then their checkers | Finite descriptive GSVA scores for the exact eight fixture samples and a final custom ORA report with truthful supplied/effective counts and ratios; scientific CSV/RDS bytes still match the prior analytic run. The two GMT sets are not a planted directional GSVA benchmark. |
| 10–11 | `python 10_string_cache.py`; `bash 11_sparse_ppi.sh`; `python 11_check_ppi.py` | Official yeast STRING v12 alias/info/link files under a 150 MiB aggregate cap, followed by the shipped constructor, mapping, interactions, score filter, graph exports, and sparse figure. |
| 12 | `python 12_artifact.py` | All required phase profiles, bounded output allowlist, relative manifest, and PNG/SVG structural previews for independent visual inspection. |

The STRING phase makes HEAD and GET requests only for the three specified `4932` archive URLs under `https://stringdb-downloads.org/download/`; redirects are refused. The shipped `STRINGdb` constructor also makes its two version GETs at `https://string-db.org/api/tsv-no-header/version` and `/available_api_versions`. It receives only public yeast identifiers. No FASTQ, count matrix, sample label, model value, or local file is sent to an external service.

Every phase fails the manual job on a missing or inconsistent output. Checkers include altered-output controls for pooled BH, ORA numeric invariance, GSVA finite values, and RiboDetector FASTQ identity. The retained Actions artifact contains only selected synthetic/public tables, reports, all produced PNG/SVG figure pairs, vector-render previews, and a manifest of relative paths, sizes, phase outcomes, and SVG-declared font families. Raw sequences, RDS objects, local logs, absolute paths, and checksum manifests are excluded. Automated parsing and rasterization do not establish absence of label overlap; every retained final PNG and SVG preview requires human visual review before the figures are accepted.
